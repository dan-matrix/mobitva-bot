# Mobitva Bot — настройка с нуля

## Что это
Telegram-бот, который ищет предметы в базе Mobitva.help прямо в чате.
Напиши боту название предмета или `/item название` — он ответит характеристиками и ссылкой.

## Шаг 1. Создать бота в Telegram
1. Открой в Telegram чат с **@BotFather**.
2. Напиши `/newbot`, следуй подсказкам (придумай имя и username бота).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — сохрани его, он понадобится дальше.

## Шаг 2. Залить код в новый репозиторий на GitHub
1. Создай **новый, отдельный** репозиторий на GitHub (не в том, где лежит сайт) — например `mobitva-bot`.
2. Залей туда все файлы из этой папки: `server.js`, `package.json`, `.github/workflows/keep-alive.yml`, этот `README.md`.

## Шаг 3. Развернуть на Render (бесплатно)
1. Зарегистрируйся на [render.com](https://render.com) (можно через GitHub).
2. Нажми **New +** → **Web Service**.
3. Выбери репозиторий `mobitva-bot`, который только что залил.
4. Настройки:
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. Во вкладке **Environment** добавь две переменные:
   - `BOT_TOKEN` — токен из Шага 1
   - `PUBLIC_URL` — адрес, который Render выдаст твоему сервису (что-то вроде `https://mobitva-bot.onrender.com`). Его можно узнать/скопировать сразу после первого деплоя вверху страницы сервиса, а потом ещё раз зайти в Environment и вписать.
6. Нажми **Create Web Service** — Render соберёт и запустит бота (первый запуск занимает пару минут).

## Шаг 4. Настроить автопинг, чтобы бот не засыпал
1. В репозитории `mobitva-bot` на GitHub зайди в **Settings → Secrets and variables → Actions**.
2. Добавь секрет:
   - Имя: `BOT_PUBLIC_URL`
   - Значение: тот же адрес, что в `PUBLIC_URL` (например `https://mobitva-bot.onrender.com`)
3. Всё, `.github/workflows/keep-alive.yml` уже настроен и начнёт пинговать бота каждые 12 минут автоматически.

## Шаг 5. Проверить
Напиши своему боту в Telegram что угодно, например "меч" — он должен ответить списком подходящих предметов.

## Если что-то не работает
- Проверь логи в Render (вкладка **Logs** на странице сервиса) — там будет видно ошибку.
- Убедись, что `PUBLIC_URL` в Environment на Render **точно совпадает** с реальным адресом сервиса (без слэша на конце).
- Если бот не отвечает совсем — возможно, обновилась переменная `PUBLIC_URL`, но сервис не перезапустился: нажми **Manual Deploy → Deploy latest commit** на Render.
