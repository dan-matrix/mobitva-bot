# Mobitva Bot — настройка с нуля

## Что это
Telegram-бот для Mobitva.help:
- **Поиск** — напиши название предмета/руны/тотема и т.д., бот ищет по всей базе, прощает опечатки.
- **Привязка аккаунта** — свяжи Telegram с аккаунтом на сайте.
- **Таймеры** — смотри, добавляй, удаляй, перезапускай таймеры прямо из чата.
- **Уведомления** — бот сам напишет в личку, когда таймер истёк.

## Шаг 1. Выполнить SQL в Supabase
1. Зайди в свой проект на [supabase.com](https://supabase.com) → **SQL Editor** → **New query**.
2. По очереди выполни файлы из папки `sql/`: `001_telegram_links.sql`, `002_watch_chats.sql`, `003_daily_whiner.sql`, `004_group_members.sql`, `005_whiner_settings.sql` — скопируй содержимое каждого, вставь, нажми **Run**. Уже выполненные раньше заново не трогай, нужен только новый `005`.

## Шаг 2. Взять привилегированный ключ (service role)
1. В Supabase зайди в **Project Settings → API**.
2. Найди раздел **Project API keys** → скопируй ключ **service_role** (НЕ тот, что "anon public" — именно service_role).
3. Держи его в секрете — этот ключ даёт полный доступ к базе в обход всех ограничений. Никогда не публикуй его на сайте или в открытом репозитории.

## Шаг 3. Создать бота в Telegram
1. Чат с **@BotFather** → `/newbot` → сохрани токен.

## Шаг 4. Залить код в репозиторий на GitHub
Залей все файлы из этой папки (`server.js`, `package.json`, `.github/workflows/keep-alive.yml`, папку `sql/`) в свой репозиторий `mobitva-bot` на GitHub (замени старые файлы новыми).

## Шаг 5. Развернуть/обновить на Render
Если сервис уже создан — просто зайди в его **Environment** и добавь третью переменную:
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ из Шага 2.

(Переменные `BOT_TOKEN` и `PUBLIC_URL` уже должны быть настроены из прошлого раза.)

Render сам подхватит новый код из GitHub и перезапустит сервис.

## Шаг 6. Залить обновлённый сайт
В репозитории сайта (mobitva.help) обнови файл `profile/index.html` — в нём появился блок «✈️ Telegram-бот» с кнопкой привязки.

## Шаг 7. Проверить
1. Залогинься на сайте → Профиль → раздел «Telegram-бот» → нажми «Привязать Telegram» → скопируй код.
2. Напиши боту в Telegram: `/link КОД`.
3. Напиши `/timers` — должен показать список персонажей (если есть).
4. Попробуй `/timer_add` — пройди мастер добавления.
5. Поставь таймер на 1-2 минуты и подожди — бот должен сам прислать уведомление, когда время выйдет.

## ИИ-ответы (/ask)
1. Supabase → SQL Editor → выполни `sql/006_ai_settings.sql`.
2. Получи бесплатный ключ (например, Google AI Studio: aistudio.google.com).
3. В Render → Environment добавь переменные:
   - `AI_API_KEY` — ключ провайдера;
   - `AI_BASE_URL` — адрес API (для Gemini: `https://generativelanguage.googleapis.com/v1beta/openai`);
   - `AI_MODEL` — название модели (для Gemini — актуальная Flash-модель из AI Studio);
   - `AI_DAILY_LIMIT` — необязательно, всего запросов в сутки (по умолчанию 40).
   - `AI_STYLE` — необязательно: `rude` (по умолчанию, «зеркальный»: с вежливыми общается нормально, на хамство и оскорбления отвечает язвительно и с матом) или `soft` (всегда мягкий, никогда не грубит).
4. Команды: `/ask вопрос`, ответом на сообщение `/ask`, для админов группы `/ask_on` и `/ask_off`.
5. Позывные («хелп,», «помощь,», «мобитва хелп,», «инфо,», «help,», «бот,») можно править в `server.js`, в списках `AI_CALLSIGNS_STRICT` и `AI_CALLSIGNS_LOOSE`.
6. **Ответы по базе.** Перед ответом ИИ бот ищет в базе сайта предметы, круги, тотемы, руны и т.д., о которых спрашивает человек, и отвечает строго по найденным данным (карточки подставляются модели как факты). Если в базе ничего нет, на вопросы про игровые факты бот честно говорит «в базе такого нет», а на болтовню отвечает свободно.
7. **knowledge.md** — файл с общими сведениями (бот сам выбирает из него слова-«крючки», так что новые разделы подхватываются без правок кода; на вопросы, где этих слов нет, файл ИИ не передаётся, чтобы экономить квоту). Файл с общими сведениями («как играть», частые вопросы). Заполни его текстом, бот прочитает его при запуске. Пустые разделы просто не помогают, ничего не ломают.
8. **Память диалога.** Бот помнит последние ~6 вопросов и ответов ИИ в каждом чате (хранится в памяти, сбрасывается при перезапуске бота и через час тишины). Видит только то, что было адресовано ему.
9. **Зеркальный тон.** Бот не язвит просто так: нормальным собеседникам отвечает нормально, а тем, кто хамит и оскорбляет его, отвечает тем же (ограничения по запретным темам действуют всегда, см. `AI_HARD_LIMITS`). **Режимы тона.** На вопросы про саму игру (предметы, механики, правила) бот отвечает мягко и по делу (максимум одна лёгкая шутка), на болтовню остаётся язвительным (`AI_STYLE=rude`). Текст режима: `AI_PROMPT_GAME` в `server.js`.
10. **Просьба «покажи предмет».** Фразы вроде «хелп, покажи палку духа», «найди …», «что за …», «характеристики …», «как выглядит …» бот обрабатывает сам, без ИИ: короткая фраза («Нашёл: …» или «Что-то подобное нашлось: …», если название неточное) и следом карточка. Квота ИИ не тратится, пересказа характеристик в тексте не бывает. Конкретные вопросы («с какого лв…», «как сделать…», сравнения) идут через ИИ, а если он всё же распишет характеристики, текст заменяется короткой фразой. Фразы-шаблоны: `AI_LOOKUP_INTROS_STRONG` и `AI_LOOKUP_INTROS_FUZZY` в `server.js`.
11. **Карточка предмета.** Если в вопросе найден предмет из базы, характеристики бот присылает отдельным сообщением в том же формате, что и `/item` (их формирует код, а не ИИ). ИИ в тексте только отвечает на сам вопрос.
12. **Диагностика ИИ.** Команда `/aiinfo` (в группах только для админов) показывает провайдера, модель, расход, последнюю ошибку и делает живой тестовый запрос. Если бот пишет «мозг недоступен», начни с неё или найди в логах Render строки `ИИ: попытка ... не удалась: AI HTTP <код>`. Коды: 429 — лимит провайдера, 400 — запрос отклонён, 401/403 — проблема с ключом, 404 — неверное имя модели, 5xx — сбой у провайдера. При 429, 5xx и таймауте бот сам делает один повтор.
13. **Проверка доменов по запросу.** «проверь домены», «проверь игру», «статус доменов», `/check_game`, а при обращении к боту («хелп, игра работает?», в личке, `@бот`) ещё и вопросы вида «домены лежат?», «что с игрой?». Бот сам проверяет `mmobitva.ru` и `mobitva.net` и отвечает статусом (без ИИ, квоту не тратит). Фоновые уведомления о падении по-прежнему включаются `/watch_game`.
14. **Шуточные ответы на тег админа.** Если в группе тегнуть (@) админа, бот отвечает случайной шуткой (список `ADMIN_TAG_REPLIES` в `server.js`; на одного админа не чаще раза в минуту, на группу не чаще раза в 10 секунд; если админ тегнул сам себя, у бота свои шутки `ADMIN_SELF_TAG_REPLIES`). Выключить: переменная `ADMIN_TAG_REPLIES=off` в Render.
15. В группе бот отвечает и без команды: на reply к его ответу, на упоминание `@имя_бота` и на фразы, начатые со слова «бот,» (последнее работает, если в @BotFather выключен Group Privacy).
Ключи нельзя хранить в коде и заливать на GitHub — только в переменных окружения Render.

## Если что-то не работает
- Проверь логи в Render (вкладка **Logs**).
- Убедись, что все три переменные окружения заполнены верно: `BOT_TOKEN`, `PUBLIC_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
- Если `/link КОД` не срабатывает — проверь, что SQL из Шага 1 выполнился без ошибок (таблица `telegram_links` должна существовать в Supabase → Table Editor).
